# KarosL v1.0.0

**Release date:** 2026-08-24. **Type:** first versioned release — no prior tags or `VERSION` file existed
before this.

## Summary

KarosL is a live accommodation-management application for a single organization managing multiple
properties — occupant registration, room/unit assignment, payment recording, receipts, a visual property
explorer, administration, audit logging, and backups. v1.0 marks the point where core business
functionality, authentication/authorization, HTTPS, database migration to Amazon RDS, off-site S3 backups,
CloudWatch monitoring, CI/CD, security hardening, and operational cleanup are all complete and verified —
see `docs/V1_RELEASE_SCOPE.md` for the exact, evidenced feature list and `docs/GO_LIVE_CHECKLIST.md` for
what was checked and how.

## Major capabilities

- Occupant, occupancy, payment, and receipt management, with a visual Property Explorer (traffic-light
  availability) and administration screens for properties/sections/units/pricing.
- Reports (occupancy, financial, occupants) with CSV/XLSX export.
- Full audit trail of business-data changes.
- 3-role RBAC (Super Administrator, Property Manager, Staff) — see `docs/ARCHITECTURE_DECISIONS.md`.

## Infrastructure

- AWS eu-north-1: EC2 (Docker Compose), Amazon RDS PostgreSQL (private, encrypted, deletion-protected),
  S3 (private, versioned, nightly `pg_dump` backups), CloudWatch (7 alarms across EC2/RDS/backup health),
  SNS email alerting (confirmed).
- HTTPS via Let's Encrypt, dual certificate lineages (hostname + bare-IP), no Elastic IP.
- CI/CD via a self-hosted GitHub Actions runner on the instance — push-to-deploy with automated tests,
  build validation, and an external smoke test on every deploy.

## Security

- Formal 3-role RBAC replacing an earlier no-op permission check; a separate, more serious
  privilege-escalation path (user-account management reachable by non-admins) found and fixed the same day.
- RDS and S3 both private, confirmed live. SSH restricted to a single administrator IP. `DEBUG=False`
  confirmed both by direct server check and external error-page probing.
- A written, five-scenario security-incident-response runbook (net-new — none existed before).

## Known limitations

See `docs/V1_RELEASE_SCOPE.md` §6 for the full, ranked list. Headline items: `.env` secrets exist only on
the EC2 instance with no second copy (rotation, not recovery, if the instance is lost); no alarm for the
backup timer silently stopping; no per-property RBAC scoping (every Property Manager is equally trusted
today — a deliberate scope decision, not an oversight, for a single-organization tool); RDS's own
point-in-time-recovery is documented but not empirically tested.

## Migration / deployment notes

No migration is required for this release — it's a point-in-time snapshot of already-deployed,
already-live functionality, not a new deployment. Nothing about how the app runs changes as a result of
tagging v1.0.0. Versioning artifacts added this release: a `VERSION` file at the repo root, and
`frontend/package.json`'s version bumped from the placeholder `0.0.0` to `1.0.0` — neither affects runtime
behavior.
